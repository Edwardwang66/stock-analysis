## How to read research status

“Current” pages describe the code and operational boundary in this checkout. “Historical research snapshot” pages preserve dated or pre-refactor findings; their claims and metrics are not current product guarantees. A script being executable does not mean its historical result is reproducible from a clean checkout: most market inputs live in ignored caches or are fetched from changing external services, and the crypto loader CLIs do not refresh cache files that already exist.

Requirements are deliberately separated by execution context:

| Execution context | Requirements file | Boundary |
|---|---|---|
| Direct research commands under `backtest/` | [`backtest/requirements.txt`](../../backtest/requirements.txt) | Python 3.11.15 hash lock for the research modules. |
| Research automation that imports both `backtest/` and `scripts/` | [`requirements/automation.txt`](../../requirements/automation.txt) | Union lock used by `alpha-routine` and `monthly-studies`; it is not the direct-install contract for every backtest command. |
| Hyperliquid operational monitor | [`scripts/requirements.txt`](../../scripts/requirements.txt) | Narrow scripts lock used by `hyperliquid-monitor`; it does not install the research stack. |
| External market and methodology reports | N/A (document-only) | No repository command reproduces the web research or freezes its external sources. |

All result values remain in the linked historical pages. The tables below catalog methods and limitations without promoting those values into current guidance.

## Reproduction policy

1. Record the Git commit, exact Python version, selected requirements lock, command and arguments, provider, data cutoff, tracked universe files, and cache provenance.
2. Install direct research from `backtest/requirements.txt`. Use `requirements/automation.txt` only when reproducing a workflow that imports both `backtest/` and `scripts/`; use `scripts/requirements.txt` for the Hyperliquid monitor.
3. Treat every live universe selection or cache refresh as a new dataset. The crypto loader CLIs do not refresh existing cache files: delete them or call the fetch functions with `force=True`, then preserve raw inputs externally if exact reruns matter.
4. Run without `--publish` unless a reviewed feed write is intended. Study scripts can overwrite a same-day result path.
5. Compare a rerun with a historical page only after documenting input differences and the methodological caveats above.

## Shared limitations

- Current constituents and current liquid listings create survivorship and future-membership bias.
- Point-in-time membership cannot recover missing delisted price histories.
- Ignored caches and live providers prevent deterministic clean-checkout reproduction.
- Crypto loader CLIs refresh tracked universes while reusing existing per-symbol caches indefinitely, so universe and cache data can have different cutoffs unless files are deleted or fetch functions are called with `force=True`.
- Several “holdout,” “OOS,” or purge labels are weaker than prospective isolation.
- Cost, borrow, locate, same-close execution, and capacity assumptions are incomplete across methods.
- Historical pages preserve evidence and terminology; they are not current product behavior or investment advice.
